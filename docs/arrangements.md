# 个人安排：文本到任务阶段

更新：2026-11-05。本页记录文本到任务基础流程；文件上传与会议处理见 [云服务接入](materials.md)。第四阶段应用内排期已开发，按用户要求未测试验收，见 [智能安排](planning.md)；外部日历未连接。

## 使用

进入网页后，顶栏增加「今日／待处理／资料」，原有对话、记忆、草稿确认、定时任务和档案入口保留。

1. 点「收集信息」，粘贴消息、文档正文或已有会议文字稿。原始时间不知道可以留空，不应填导入时间代替。
2. 保存后打开资料。有模型配置时可点「使用模型整理」；没有模型时，从原文选取连续片段，点「手动添加事项」。
3. 在「待处理」核对标题、归属、出处和时间。选择创建任务、关联已有任务、仅保存参考或忽略。非本人归属须明确勾选愿意承担，才能创建个人任务。
4. 在「今日」查看未完成、今日截止、逾期或已结束任务。可编辑状态、截止时间、耗时、优先级和备注；查看出处会突出显示对应原文片段。
5. 可在确认时配置独立的站内提醒时间。任务完成或取消后撤销未来提醒；提醒送达不会把任务标成完成。
6. 在任务详情查看变更历史。刷新页面后，资料、处理决定、任务和历史仍在当前服务器会话下。

「今日」增加了应用内时间线、可用时段、固定安排和排期建议，原任务清单保留。「资料」有上传文件和读取网页入口；OCR、转写、速读和问答需要云配置，应用内排期无需模型 Key。

## 启动

需要 Python 3.12。本轮已在 `.venv/` 安装项目锁定依赖，并创建仅供本地使用的 `.env`；该文件不应提交或分享。

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8787 --env-file .env
```

打开 `http://127.0.0.1:8787/#today`。本轮本地配置使用 `DATA_DIR=./data/local`，并启用仅在进程运行期间工作的提醒调度器；服务停止时不会触发提醒。模型 Key 尚未配置，当前实际可用的是手动整理与任务管理；模型提取通路只进行了测试替身验证。

本地网页会话仍使用原项目的签名 Cookie，无独立账号密码。清除 Cookie、换浏览器或 AUTH_SECRET 会影响原会话的访问，请保留本地配置和数据目录。

可按现有 [模型网关说明](llm-gateway.md) 配置实际模型，再实测提取质量。不要把真实凭据贴在对话或资料正文中。

## 数据和边界

- 四个新私有表：`arrangement_sources`、`arrangement_candidates`、`arrangement_tasks`、`arrangement_changes`。
- 使用既有 DAL 的用户隔离；Postgres 部署需要用原有 owner migration 更新 schema 与 RLS，再启动新版本。当前没有真实 Postgres 实测。
- 原文固定保存；候选引文必须逐字对应连续原文，保存字符位置。日期由用户核对填写，模型只保留原始时间表达。
- 同一用户重复提交相同资料复用记录；同一候选确认的相同重试返回原结果。与已处理决定不同的请求返回冲突。
- 任务编辑带版本号；旧页面覆盖更新返回冲突。任务、候选决定、提醒和变更历史在同一事务中写入。
- 提醒复用既有 schedule 验证、启用数量上限和调度器；只送站内收件箱，未增加对外发送。
- 模型整理使用版本化提示词、结构校验、原文引用核对、既有输出检查、用量额度与轨迹。未配置模型或失败时不伪造摘要／候选项。
- 密码、Cookie、联系方式和既有隐私沙盒值在写入前拒收；来源内容不能作为执行指令。
- 模型调用中断后，处理中状态可在 3 分钟后重新发起；成功整理的资料不会反复请求模型。
- 本阶段每次文本最多 20,000 字，模型结果最多 30 条候选。原资料列表 API 读取最近 200 份，候选列表读取 300 条，任务列表读取 500 项。资料页面已改用支持筛选和分页的知识库接口，见 [资料检索](library.md)。
- 文件处理见 [材料处理](materials.md)；时间块、容量与改期见 [智能安排](planning.md)。批量采纳候选、外部日历自动同步、自动收件和会前准备仍在后续范围。

## API

均须既有会话认证，成功结果为 `{ok: true, data: ...}`。身份只来自服务端会话。

| 方法 | 路径（前缀 `/api/arrangements`） | 作用 |
|---|---|---|
| GET | `/status` | 模型、调度器与尚未接入能力的状态 |
| GET / POST | `/sources` | 列出／保存文本来源 |
| GET | `/sources/{id}` | 原文、摘要和候选项 |
| POST | `/sources/{id}/analyze` | 模型整理，失败保留原文 |
| POST | `/sources/{id}/candidates` | 手动添加有原文依据的候选项 |
| GET | `/candidates` | 待确认事项 |
| POST | `/candidates/{id}/decide` | 明确确认后采纳／关联／参考／忽略 |
| GET | `/tasks` | 私有任务清单 |
| GET / PATCH | `/tasks/{id}` | 查看任务与历史／按版本确认更新 |

## 验证

接口与数据测试：

```bash
.venv/bin/python -m pytest -q tests/test_arrangements.py
```

可选的 DOM 集成测试会通过真实本地 HTTP API 保存资料、确认任务、等待真实调度器送达提醒、更新完成状态，并重新加载验证恢复。使用全新的测试会话和标为「合成验收」的输入，不采用用户浏览器 Cookie。

```bash
npm install --prefix data/ui-qa --no-audit --no-fund jsdom
node --experimental-vm-modules tests/arrangements_ui.mjs http://127.0.0.1:8787
```

测试需要服务器运行、模型未配置、`PROACTIVE_ENABLED=1`、较短的 `PROACTIVE_TICK_SECONDS`（本地为 10 秒）。DOM 原生对话框、滚动与尺寸观察使用模拟，不验证真实 Chrome 布局、焦点表现或移动端视觉。

原有测试有一个归档环境问题：`test_manifest_records_run_config` 要求非空 Git SHA，但当前目录没有 `.git`。本轮先记录了这个基线失败，回归时单独排除该项，没有创建 Git 仓库或修改该测试以掩盖问题。
