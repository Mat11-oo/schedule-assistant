# 第四阶段：应用内智能安排

更新：2026-11-05。**功能代码已开发；按用户要求暂不进入测试和验收。** 本页描述实现，不代表测试通过。模型 Key 保持留空，由用户最后在本机填写。

## 本阶段范围

| 功能 | 实现 |
|---|---|
| 可用时段 | 按周设置多个工作时段；留空休息；上海时区 |
| 容量与缓冲 | 每天任务投入上限及安排之间的缓冲；固定会议另外占用可用区间 |
| 固定安排 | 手动登记、修改、取消；保留并提示真实冲突，不自动移动其他安排 |
| 工作量与前置关系 | 总预计／剩余耗时、能否拆分、最小时间块、前置任务与循环检查 |
| 排期建议 | 按前置关系、截止时间、优先级及创建时间分配；列出耗时未知、未安排及容量缺口 |
| 预览确认 | 区分新增、取消、保留与未安排；确认后原子保存时间块及历史 |
| 锁定与改期 | 锁定项不自动重排；单块改期先预览，移动锁定项需明确解锁许可 |
| 今日与待处理 | 今日按日期展示时间线；未确认方案同时在待处理保留 |
| 恢复与版本 | 预览持久化，有效 30 分钟；保存前重读版本与输入快照；重复确认返回原结果 |
| 日历导出 | 所选日期导出 `.ics`，用户手动导入其他日历 |

排期采用确定性的区间分配规则，无需模型密钥，是启发式建议，**不保证全局最优**。

外部日历尚未连接，只检查本应用已知安排。第三方 OAuth、自动读取、远端版本回查、写入及失败恢复，需要确定日历服务和授权范围后单独接入。不能保证用户未录入的其他日程没有冲突。

## 使用流程

1. 在「今日」打开「可用时段与容量」，核对并保存。第一次显示的是可编辑示例，确认前不作为用户偏好。
2. 登记已有会议、课程、约会等固定安排；休息时间留在可用时段之外。
3. 在「任务排期信息」填写剩余耗时、能否拆分和前置任务；总预计、截止时间与状态从任务详情编辑。
4. 选择 1–31 天的日期范围，点「生成排期建议」，选择任务。勾选重排时，预览会列出将取消的原时间块。
5. 核对每天容量、新增、取消、保留与未安排事项。部分安排需要额外勾选已了解缺口及取消项。
6. 确认后保存到应用内。若任务／日程已变化、预览过期或开始时间已过，重新生成方案。
7. 临时有事先登记新固定安排，查看冲突，再选择单块改期或任务重新排期；系统不会自行移动已确认安排。
8. 需要带到其他日历时手动导出文件，并在实际日历中核对导入结果。

工作时段格式：`09:00-12:00, 13:00-18:00`。同日时段不能重叠；跨午夜的偏好拆成两天填写。单个自动任务时间块不跨午夜。

## 任务、时间块与提醒

- 时间块是计划，不自动修改任务状态，也不根据时间流逝扣减工作量。
- 剩余耗时留空时使用总预计；都未知则不排。剩余为 0 也不会自动完成任务。
- 尚未结束的已确认时间块计入未来预留工作量；过去的时间不当作已完成工作。当天计划分钟计入当日容量，仍不是实际工时统计。
- 默认整段安排；允许拆分后遵守最小时间块。时间不足、截止已过或前置任务排不完时，列出缺口，不延长用户工作时段或承诺新截止时间。
- 前置任务已完成，或其工作能完整排在当前任务前，才继续安排；计划顺序不代表前置工作实际完成。
- 单块改期保持原时长；工作量变化时先修改剩余耗时，再取消或重新安排未来时间块。
- 明确将任务改成完成、取消或等待，会撤销尚未结束的时间块（包括锁定项），保留计划历史；不推断实际耗时。
- 提醒仍使用既有站内提醒入口；时间块不另建自动提醒。完成或取消任务仍撤销未来提醒；提醒送达不代表完成。

## 保存、隔离与限制

预览刷新后可从待处理或今日继续查看，最多显示最近 10 份有效预览。确认在同一事务中核对日程版本与快照，拒绝旧预览覆盖新安排。首次创建固定安排由客户端提供提交 ID；同一请求重试复用原事件，参数变化则返回冲突。

SQLite 沿用 `BEGIN IMMEDIATE`；Postgres 使用日程行锁和按用户的事务 advisory lock，涵盖首次日程创建。六张新增私有表接入既有 DAL 与 owner RLS migration；不修改原任务表字段。Postgres 需先由 owner 执行原有迁移，本轮未连接。

当前限制：单次查看／排期 1–31 天，自动排期起始在未来一年内；最多选择 500 项任务；一次读取最多 1000 条任务、1000 条排期设置、5000 条相关事件／时间块；一份方案最多新增 2000 个时间块。每任务最多 30 个前置任务，层级最多 100 层。超限拒绝，不静默截断。

`.ics` 实现依据为 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545)：UTC 起止时间、稳定 UID、版本序号、文本转义及 UTF-8 字符边界折行。只导出时间和标题，不附来源全文或转写。

**导出是文件交换，不是自动同步。** 应用内取消或改期不会自动修改已导入的外部记录；相同 UID 的处理与实际导入结果仍需在用户所选日历中验收。

## 维护与接口

主要维护源：`app/planning/`、`app/data_access/planning.py`、`static/js/planning.js`；任务状态联动位于 `app/data_access/arrangements.py`。

新增表：`planning_calendars`、`planning_events`、`planning_timings`、`planning_blocks`、`planning_proposals`、`planning_changes`。旧时间块与修改前后内容保留在历史中。

接口前缀 `/api/arrangements/planning`，身份来自服务端会话。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/state?start_date=…&end_date=…` | 设置、安排、冲突、排期信息与预览 |
| PUT | `/preferences` | 确认工作时段、容量与缓冲 |
| POST / PATCH | `/events` / `/events/{id}` | 确认登记／修改固定安排 |
| POST | `/events/{id}/cancel` | 确认取消固定安排 |
| PUT | `/tasks/{id}/timing` | 剩余耗时、拆分与前置关系 |
| POST / GET | `/proposals` / `/proposals/{id}` | 生成／恢复方案 |
| POST | `/proposals/{id}/confirm` 或 `/dismiss` | 确认或放弃方案 |
| POST | `/blocks/{id}/move-preview` | 单块改期预览 |
| PATCH | `/blocks/{id}/lock` | 确认锁定／解锁 |
| POST | `/blocks/{id}/cancel` | 确认取消未来时间块 |
| GET | `/history` | 最近 100 条历史 |
| GET | `/export.ics` | 鉴权下载日历文件 |
