# 第五阶段功能贯通

更新于 2026-11-05。每日简报、重复事项提示和来源变更确认已加入代码，测试与验收按用户安排后置。Key 由用户最后在本机填写。

## 每日简报

「今日」汇总本应用内的安排、临期和逾期任务、等待事项、冲突及待决定事项。临期范围可选 1 至 14 天，包含当天。各分组可能重叠，每组任务最多展示 50 项，日程最多 100 项，冲突和问题各最多 100 项。

简报设置可选择内容和每日时间，采用上海时区。定时推送默认关闭，用户确认开启后，现有后台调度器按日写入站内收件箱。应用与全局提醒调度器运行时才会处理，错过时间后补一份当天简报。设置关闭后，任务和既有快照继续保留。

快照、收件项和当日生成记录一起提交，按用户日程锁串行化。手动保存会另外创建快照，页面显示最近 10 份。已保存简报保留生成时内容，任务入口打开当前记录。

## 重复事项提示

在候选事项的「核对并处理」中显示可能相同的任务，最多 8 项。规则使用规范化标题、文字相似度和同一资料的版本关系，标题相同或接近时给出核对依据。规则可能漏掉语义相同而措辞不同的工作，不同日期或轮次的任务也可能被提示。

用户可以选中已有任务，再点击确认关联来增加出处。选择「这不是同一件事」后，该候选和任务组合的判断会保存。新候选需要独立判断。已完成任务可以增加出处，状态沿用用户已有决定。

## 来源变更确认

候选事项提供「用来源核对已有任务」入口，重复提示也可进入相同流程。

1. 选择已有任务，查看引文、来源原始时间及时区。
2. 明确选择修改名称、截止时间或责任处理。截止时间由用户核对填写，勾选修改后留空表示明确清除。
3. 责任处理可以保留当前状态、改为等待他人，或取消个人任务。已结束任务需先从任务详情明确恢复，才能应用新的变更。
4. 填写依据后生成新旧对比，预览有效 30 分钟，可从待处理恢复。
5. 用户确认后检查任务版本与候选状态，更新任务、关联出处并保存变更历史。

任务已变化、候选已被处理或预览过期时，需要重新核对。重复确认复用原处理结果。日期变更会使旧排期预览失效，已有未来时间块由用户核对并选择重新排期。等待或取消会撤销尚未结束的时间块，取消同时撤销任务提醒。

任务详情的变更历史显示依据、引文与字段差异。删除文件来源时，相关变更预览和重复判断一起清理，历史引用按现有删除规则处理，确认保留的个人任务继续保存。

## 模型依赖与数据

这些跟进功能基于数据库记录和文字规则。模型 Key 用于已有的资料理解、转写与候选提取流程。语义匹配和自动识别来源变更需要后续按实际样本增强，当前用户可以通过手动候选和字段核对完成流程。

主要维护源为 `app/data_access/followup.py`、`app/arrangements/followup_api.py`、`app/arrangements/followup_schemas.py`、`app/arrangements/briefs.py` 和 `static/js/followup.js`。

四个新增私有表分别保存简报偏好、简报快照、重复判断和来源变更预览，已注册到既有 DAL 与 owner RLS migration。Postgres 需由 owner 执行项目原有迁移。

接口前缀为 `/api/arrangements/followup`。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/brief` | 当前简报、设置与最近快照 |
| PUT | `/brief-preferences` | 确认简报内容和时间 |
| POST / GET | `/briefs` / `/briefs/{id}` | 保存与读取快照 |
| GET | `/candidates/{id}/matches` | 可能重复的任务 |
| POST | `/candidates/{id}/distinct` | 保存独立事项判断 |
| POST | `/candidates/{id}/updates` | 创建来源变更预览 |
| GET | `/updates` | 最近 50 份有效变更预览 |
| POST | `/updates/{id}/confirm` | 确认应用变更 |
| POST | `/updates/{id}/dismiss` | 放弃变更建议 |
